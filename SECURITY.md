# Security policy

## Report a vulnerability

Use [GitHub's private vulnerability reporting form](https://github.com/OscarFrog/yt-dlp-aria2-downloader-gui/security/advisories/new)
to report a suspected vulnerability to the maintainer. Reports in English or
French are welcome. Keep vulnerability details out of public issues, pull
requests and Discussions while the report is being assessed.

Include the application version or source commit, platform, affected component,
steps to reproduce and potential impact. Use a minimal example with synthetic
data where possible. Do not send real cookies, tokens, credentials,
authentication headers, private media URLs, personal data or unredacted logs,
even in a private report. Review sanitized logs too: media titles and local
paths can remain personal.

Coordinate disclosure with the maintainer before publishing technical details.
For ordinary bugs or usage questions, use the public
[bug report](https://github.com/OscarFrog/yt-dlp-aria2-downloader-gui/issues/new?template=bug-report.yml)
or [Discussions](https://github.com/OscarFrog/yt-dlp-aria2-downloader-gui/discussions).

## Maintainer coordination

Assess the report in the private advisory and clarify its impact with the
reporter. Prepare and review any fix privately, using a temporary private fork
when appropriate. Agree on disclosure with the reporter, then publish the
advisory with the affected versions, available fixes and any mitigations.

## Versions and response expectations

State the exact version you tested. If practical, mention whether the issue
also affects the [latest published release](https://github.com/OscarFrog/yt-dlp-aria2-downloader-gui/releases/latest)
or `main`; this is not a prerequisite for reporting a vulnerability.

The project has no published support-lifetime or backport schedule for older
versions, and no guaranteed response or remediation deadline. Do not assume
that an older release receives security updates. Published
[security advisories](https://github.com/OscarFrog/yt-dlp-aria2-downloader-gui/security/advisories)
and release notes identify affected and fixed versions when available.
